Scraps / self-hosted agent compute

Turn your idle compute into a private agent cloud.

Scraps gives Pi disposable development computers on hardware you control. Pi stays local. Project files, commands, builds, and tests run on the spare machine.

01 / Install it on a spare computer

Start with an ordinary Linux VM.

The VM can live on a Proxmox server, a spare computer, or your current machine. Scraps installs scrapd, OpenShell, and the workspace runtime inside it. The host is never used as the workspace.

On your current computer

Lima creates the worker VM for you.

pnpm install
make configure
make up

On a spare computer or Proxmox host

Create an Ubuntu 24.04 VM, join it to your Tailscale network, then deploy the worker from your Scraps checkout.

make deploy-worker REMOTE=you@worker
ssh you@worker sudo scraps-worker tailscale-serve
make configure-remote-client REMOTE=you@worker
scrap status

One worker VM can hold many isolated, disposable OpenShell workspaces. The service stays on your private network.

02 / Use it from Pi

Open Pi. Ask for a computer.

Pi starts normally on your computer. Run /scrap when you want the project to move into a remote workspace.

$ pi
› /scrap
✓ workspace ws_7f2d attached

› run the tests and fix what fails

Scraps replaces Pi’s project-facing tools with remote versions. bash, read, write, edit, ls, find, and grep now operate inside the workspace.

Stays local
Pi, models, provider setup, prompts, skills, sessions, and the terminal UI.
Runs remotely
Project files, shell commands, dependency installs, builds, and tests.

When you are finished, toss the workspace. Pi’s tools return to your local computer.

› /scrap toss
✓ workspace deleted; local tools restored

Scraps is an early prototype. It currently supports Pi, one Linux worker VM, and OpenShell workspaces.
